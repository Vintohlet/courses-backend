# Performance results

Measurements of `GET /api/courses/recommendations` (authenticated user, collaborative strategy).

## Code versions

| Variant | Commit | Description |
|---|---|---|
| `v0-baseline` | `d7ce9ce` | First collaborative aggregation: a `$lookup` per seed course for neighbors, then a `$lookup` per seed-neighbor pair. |
| `v1-dedup` | `06fef4e` | Neighbors are grouped first, so the second `$lookup` runs once per distinct neighbor (about 2 247 lookups on `large`). |
| `v2-two-step` | `1a066ed` (T4) | No `$lookup`: a fixed number of queries (history, neighbors, neighbor enrollments, candidate courses, cards) and scoring in code (`src/services/collaborative-scoring.ts`). Same scoring semantics. |

Indexes are identical in all variants.

## Dataset

Generated by `npm run perf:seed -- --scale=<scale>` in the `courses_perf` database (deterministic synthetic data, see the main README).

| Scale | Users | Courses | Enrollments per user |
|---|---:|---:|---:|
| `small` | 100 | 40 | 6 |
| `medium` | 1,000 | 200 | 10 |
| `large` | 5,000 | 500 | 20 |

Benchmark user: `perf.user.000001@example.com`.

## Files

Naming: `<variant>-<kind>-<dataset or user>.<ext>`.

- `v1-dedup-large.csv` — benchmark runs (columns: `timestamp,dataset,variant,run,...` from v2 onward; the first v1 file predates the `variant` and `run` columns and has the older header).
- `v1-dedup-explain-user000001.json`, `...user002500.json`, `...user004999.json` — saved `explain("executionStats")` output of the aggregation for three users.
- v2 files (to be added) should be named `v2-two-step-large.csv` and `v2-two-step-explain-user<N>.json`.

Run benchmarks with `--variant=<variant>` so the CSV rows are self-describing, and compare variants on the same machine with the same request counts.
